# Display input observer

This macOS fixture records only AppKit events delivered to its own windows. It does not inject input, install a global event tap, request permissions, or declare a test passed. Use it to verify the actual source window receives tablet input; transport Applied acknowledgements alone do not prove that.

```sh
xcrun swiftc -O -target arm64-apple-macosx13.0 benchmarks/display/workloads/display-input-observer.swift -o out/display-input-observer
out/display-input-observer --target-display 42 --output out/display-input-observer.json --fill --activate --seconds 600
```

Pass the exact locally observed capture display ID. A target window appears on that display; if it differs from `CGMainDisplayID()`, a separate main-display guard window also appears. There is no automatic display selection or main-display fallback. Without `--activate`, the fixture orders its windows without explicitly taking keyboard focus. With it, the target's keyboard test field becomes first responder. `--fill` fills the target's usable screen area; otherwise it uses a centered rectangle up to 1000×720 logical points.

`OUTPUT.ready.json` contains initial geometry and zone centers. `OUTPUT` is an atomic snapshot updated at most 20 times per second while events arrive. It includes per-window move/down/up/drag/scroll/key-down/key-up/modifier counters and the newest 1024 events, with a dropped-event count. Counters retain the full run. Numbered zones show visible tap, double-tap, right-click, drag, scroll and pointer targets. Drag trails, pointer marks, event counts and scroll totals change only after actual delivered events.

`global_point`, `source_content_bounds`, `source_display_bounds` and zone `global_center` use CoreGraphics logical coordinates with top-left origins. Local points use the flipped view's top-left origin. Cocoa coordinates are reported separately. `source_normalized` describes a point relative to the actual captured display bounds, not the negotiated canvas. Map its global point through the source's authoritative fitted content rectangle when mirroring; account for the tablet's outer fitted video rectangle separately. Retina backing scale is metadata, not an extra input-coordinate multiplier.

For each gesture, compare target events with a captured baseline of the main guard counters. Require native down/up pairs, expected button/click count and local/global position, actual drag movement and nonzero scroll deltas. The main guard should receive no gesture events. Physical Mac pointer movement or user interaction can affect guard counters, so preserve a fresh baseline and keep that display untouched during acceptance. Event timestamps and observation times are injection outcome evidence, not optical latency measurements.

Send SIGTERM or SIGINT to stop. The fixture writes a final snapshot, closes only its windows, and restores the previous application only if this fixture still holds foreground focus. It also stops after the bounded duration or when its target display disappears. Caller controls launch, focus and cleanup.

The footer contains a plain editable keyboard test field limited to 256 UTF-16 code units. `keyboard_field` reports its current local rectangle and normalized source center; use these fresh coordinates after launch instead of older gesture-zone coordinates. `keyboard_text`, `keyboard_editor_first_responder` and `window_key` report actual AppKit editor state. This is a disposable text field: do not enter credentials or personal text. Text in these owned fields is included in the snapshot.

Keyboard events are observed in each owned window's `sendEvent`, before normal AppKit dispatch, including shortcuts handled before `keyDown`. They are not global observations. The `keyboard` object contains the Mac virtual key code, repeat bit, native modifier flags and portable mask (shift=1, control=2, option=4, command=8). `input_origin` distinguishes `extend-tagged` events (`source_user_data=0x504f5254`) from unmarked physical or other input. Per-event characters are retained only for Extend-tagged key events; modifier events have no character text. Keyboard events have `position_valid=false`: their incidental mouse coordinates and zone must not be used as keyboard targeting evidence.

For a keyboard interval, require the exact target window/display, first-responder state, tagged key-down/up pairs and expected modifier transitions. Match repeat events only to a held key; after a release action, require corresponding key-up and modifiers cleared, then verify a fresh plain key has no stale modifier. Also inspect the resulting bounded `keyboard_text` for the expected disposable ASCII string. Keep the physical Mac keyboard untouched and compare the separate main guard baseline. A text match alone does not prove balanced releases, lifecycle cancellation, IME composition or input latency. The Android observer driver currently provides touchscreen sequences, not held hardware-key sequences; a separate explicit key sequence is needed to test held-key cancellation.

Focus-only transitions update `OUTPUT` immediately on the AppKit window become/resign-key and application activate/deactivate callbacks. The existing 20 Hz timer also detects first-responder changes without requiring a new input event. `focus_sequence` and the newest 64 `focus_events` preserve the transition reason, application-active state, owned window key/first-responder states and local observation time; `snapshot_uptime_ns` identifies each saved snapshot. These are local evidence timestamps, not input latency measurements.

Before a keyboard interval, require the target's `keyboard_focus_active=true`, meaning the application is active, that exact window is key, and its text editor is first responder. `keyboard_editor_first_responder=true` alone is insufficient: an inactive window can retain its first responder. Preserve focus events throughout the interval and reject keyboard acceptance if focus leaves the target or any tagged keyboard event reaches the main guard. Reactivating focus after a misdirected interval does not make the original interval valid.
